# 02 · 踩坑记录

> 全部是这次真踩到、并且有明确现象/修法/验证的坑。每条按「现象 → 根因 → 修法 → 验证」写，方便以后照方抓药。
> 分五组：A 构建与工具链 / B 渲染 / C 交互与窗口 / D 数据与网络 / E 系统集成。

## A. 构建与工具链

### A1. csc 遇到中文路径直接失败

**现象**：`csc.exe /win32manifest:C:\projects\gw-quota\...` 报 `CS2005: 选项 "/win32manifest:" 缺少文件规范`，源码也找不到；但路径明明存在。

**根因**：系统自带的 `csc.exe` 在解析命令行参数时对非 ASCII 路径处理有问题（工作目录/参数转换丢字符），不是权限也不是引号问题。

**修法**：构建脚本先把 `src`、`build` 拷到纯 ASCII 的 `%TEMP%\gwquota-build\`，`Push-Location` 进去用**相对路径**编译，成功后把 exe 拷回 `dist\`。

**验证**：`build.ps1` 从此在本目录（含中文）稳定出包。

### A2. PowerShell 脚本存成 UTF-8 无 BOM → 中文全部变乱码，语法报错

**现象**：`powershell -File build.ps1` 报
`Unexpected token '鍥炬爣鐢熸垚澶辫触" }'`，`.ps1` 里中文全成乱码。

**根因**：Windows PowerShell 5.1 对**无 BOM** 的脚本按系统 ANSI（GBK）解码；UTF-8 的中文被当 GBK 读 → 字符串里的引号配对错乱 → 语法错。

**修法**：`.ps1` 一律**存成 UTF-8 with BOM**（`New-Object System.Text.UTF8Encoding($true)`）。C# 源码不受影响（编译时加 `/codepage:65001` 即可）。

**验证**：首字节 `EF BB BF`；powershell 与 pwsh 都能跑。

### A3. 编译出来的 exe 没有版本信息 → 加重 SmartScreen 嫌疑

**现象**：文件属性里 `FileVersion 0.0.0.0`、公司/产品/描述全空、无图标、未签名（`Get-AuthenticodeSignature` → `NotSigned`）。

**根因**：裸 csc 编译只写最小 PE 头，不写 Win32 版本资源。SmartScreen 的「发布者信誉」和 Defender 云查杀对一个「没有身份、没有签名、哈希又是全新的」二进制只能判为未知。

**修法**：加 `src/AssemblyInfo.cs`（`AssemblyTitle/Product/Company/FileVersion/Copyright`）+ 内嵌多尺寸图标 + 标准 manifest；并**避免反复重编译**（每次都是新哈希，信誉归零重来）。

**验证**：`Get-Item exe` 的 `.VersionInfo` 有值；属性页正常；README 第七节给了签名方案价格。

## B. 渲染

### B1. `using (Font f = 缓存字体)` 把缓存对象 Dispose 了 → 整幅画面只剩底色

**现象**：第一个球画出来了，之后每次重绘只剩一个纯色圆，日志里：
`paint-ex: System.ArgumentException: 参数无效。 在 System.Drawing.Graphics.MeasureString(...)`

**根因**：字体做了静态缓存，绘制时又用 `using` 包了 `Gfx.F(...)` 的返回值 —— 第一次绘制结束时把**缓存里的那个 Font** 释放了；第二次绘制拿到的是已释放对象，GDI+ 对无效句柄抛 `ArgumentException`。

**修法**：两种都行，本次选「不缓存」——每次 `new Font(...)`，交给 `using` 释放。绘制频率是「5 分钟一次 + 交互时几次」，这点分配完全无所谓。

**验证**：连续重绘 100 次无异常；日志不再出现 `paint-ex`。

### B2. 数字只显示半截：「92」画成「9」

**现象**：球心只出现「9」，后面「%」隔得老远 —— 不是颜色问题，是**第二位数被吃掉了**。

**根因**：用 `StringFormat.GenericTypographic` 测宽得到 31.75px，而 `DrawString` 实际排版宽度约 41.9px（含字距/尾部 padding）。矩形按 31.75+8 给，`Alignment=Center` 时 GDI+ 按自己的排版宽度裁切 → 末位被截。

**修法**：测量与绘制统一；矩形宽度 = `MeasureString`（普通格式）宽度 + 20~28px 余量，并且用 `Alignment=Near` 从左起画（不依赖居中裁切）。

**验证**：单独写了个最小复现（两个矩形画同一个「92%」）确认了截断边界，再改代码。

### B3. `Region` + `Form.Opacity` 做不出软边投影

**现象**：球边缘是硬切圆，放大有锯齿；外投影根本画不出来（Region 之外一律裁掉）；调透明度时连文字一起发灰。

**根因**：`SetWindowRgn` 是**二值**剪裁（在/不在），没有中间态；`Form.Opacity` 是**整窗一个 alpha**。

**修法**：换 `UpdateLayeredWindow` 逐像素 alpha。位图必须用 `Format32bppPArgb`（预乘）否则半透明边缘发亮；整窗 alpha 固定 255，半透明只画在背景层。

**验证**：截图放大看边缘是渐变过渡；低透明度下文字依旧清晰。

### B4. 球面高光把数字冲白了

**现象**：球左下暗、右上亮是对的，但「92」的后半截跟高光糊在一起看不见。

**根因**：镜面高光椭圆覆盖了数字区域，且文字色本身就是浅色。

**修法**：高光缩小上移（`S*0.44 × S*0.26`，中心偏左上）、alpha 降到 ~88；数字底下加一层径向暗色衬底（alpha≈115）+ 1px 暗影。

**验证**：在亮色壁纸、深色视频、纯白网页三种背景下截图，数字都可读。

### B5. `Segoe UI` 画中文出豆腐块

**现象**：详情面板里「重置」显示成两个实心方块，而同面板的「已用」「剩余」正常。

**根因**：那一列字体写的是 `Segoe UI`（无 CJK 字形）。字体族缺失时 GDI+ 不一定走字体链接，小字号下直接画成缺字方框。

**修法**：**所有可能含中文的文本统一用 `Microsoft YaHei UI`**；`Segoe UI` 只留给纯数字/百分号（球心大数字）。

**验证**：面板全文无方块。

## C. 交互与窗口

### C1. `TopMost = true` 并不等于「永远在最上层」

**现象**：切到某些全屏/顶层窗口后，悬浮球被压到下面，要切回桌面才又露出来。

**根因**：`TopMost` 只是把窗口放进顶层带；同带内其它窗口（或系统自己的顶层窗口）后来居上时，你的窗口就沉下去了。属性已经是 true，再赋一次也不会重排 z 序。

**修法**：1.5 秒定时器调 `SetWindowPos(hwnd, HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`，把自己反复插回顶层带顶部。

**验证**：全屏播放器/其它置顶工具打开时仍在上层。

### C2. 右键菜单被自己的详情面板挡住

**现象**：右键弹出菜单，但菜单被悬停面板盖住一半，点不到。

**根因**：菜单是普通弹出窗口，悬浮窗和面板都是 `TopMost`；而且当时的 `SetMenuOpen(true)` 只设了个标志位，**并没有真的去收面板**。

**修法**：`Opening` 里调 `HideDetailForce()`（无视「常显」设置强收）+ `_menuDepth++`；`Opened` 里对菜单窗口 `SetWindowPos(HWND_TOPMOST)`；菜单开着期间暂停顶层重申；`Closed` 恢复。

**验证**：菜单完整压在球上面。

### C3. 微调字体导致「重置」列被面板右边缘裁掉

**现象**：详情面板右列「20:47 重置」，最后的「置」被窗口圆角切掉。

**根因**：面板宽度是按基准宽 × 缩放算的，列位置用的是**绝对偏移**，两者一起变就错位。

**修法**：把该列改成右对齐 + 独立矩形（`lineRight - padX - 176*s`），并把整列字号提到 7.6pt；后来整块面板放大 1.35 倍、宽度收到 85%，也仍然用右对齐兜住。

**验证**：`12-19 22:06` 这种最长串也完整显示（实测面板 397×387）。

### C4. 贴边后「看着浮在中间」

**现象**：把球拖到屏幕边上，可见球离屏幕边还有 18px，像没吸住。

**根因**：窗口比可见图形大一圈（18px 投影留白），钳制是按窗口边界算的。

**修法**：吸附时允许窗口向屏幕外探出 **2/3 留白**（`ClampToScreen(rect, overhang)`），可见图形离边只剩 1/3 → 球 6px、条 4px。

**验证**：拖到顶部，窗口 y=-9，可见上边距屏幕 4px（原来 13px）。

### C5. 悬停判定用 `MouseEnter/Leave` 会漏

**现象**：从球移到面板的瞬间面板就消失了；拖动时也会闪。

**根因**：分层窗口 + 置顶窗口 + 菜单弹出，`Enter/Leave` 的到达顺序和时间不可靠。

**修法**：110ms 定时轮询 `Cursor.Position`，自己维护 `_lastIn/_insideSince` 与「离开 420ms 后再收」的迟滞。

**验证**：球→面板→菜单来回移动，面板不闪、不提前消失。

## D. 数据与网络

### D1. 启动时补刷新撞上限速，偶发 429

**现象**：刚启动就拿到 429，界面闪一下「限流退避」。

**根因**：启动 400ms 后首轮拉取；5 秒后的 boot 定时器又 `RefreshNow()`，两次请求间隔 <1s，服务端限制 1 次/秒。

**修法**：① 轮询器内部强制「距上次请求 ≥2.5s」；② boot 定时器只在**还没有数据**时才补刷。

**验证**：连续重启 10 次无 429；日志中 429 只可能来自人工狂点「立即刷新」。

### D2. 受限环境下写 `%APPDATA%` 被拒，配置记不住

**现象**：程序能读到 key，但 `config.ini` 从不生成，日志里有
`UnauthorizedAccessException: 对路径"C:\Users\...\AppData\Roaming\GWQuota\config.ini"的访问被拒绝`。

**根因**：某些会话（沙箱/受限令牌）里，子进程写漫游目录被 ACL 拦住，而**读**是允许的——所以表现为「能读 key、不能写配置」，很容易误判成代码 bug。

**修法**：数据目录**逐级探测可写位置**：`%APPDATA%` → `%LOCALAPPDATA%` → `exe 同目录\data\`，探测方式是「建目录 + 写探针文件 + 删掉」，三步都成功才算可写。key 则反过来按「数据目录 → %APPDATA% 标准位 → exe 同目录」查找，保证换位置也能找到。

**验证**：受限环境自动落到 `dist\data\`，配置正常写入。

### D3. 「打开配置目录」报 `explorer.exe - 应用程序错误 (0xc0000142)`

**现象**：菜单点「打开配置目录」，弹出应用错误框，`0xc0000142`（STATUS_DLL_INIT_FAILED）。

**根因**：代码里 `Process.Start("explorer.exe", dir)` 是**再起一个 explorer 进程**；在受限令牌/受限桌面下这个新进程初始化失败。

**修法**：改用 `ShellExecuteW("open", dir)` 交给**已在运行的外壳**处理，失败再退 `Process.Start(psi{UseShellExecute=true})`；两路都失败才弹中文错误框。（后来这条菜单项按需求删掉了，但 `OpenFolder()` 仍是正确写法。）

**验证**：正常桌面下直接打开目录。

### D4. JSON 数值类型不稳定

**现象**：`percent` 有时是 `int`、有时 `decimal`/`double`，直接强转会偶发异常；`available` 在 DeepSeek 是**布尔**、在 Kimi 是**数字**。

**根因**：`JavaScriptSerializer` 按字面量推断类型；上游两家实现不一致。

**修法**：统一 `J.ToNum(object)` 走 `Convert`/多类型分支；`available` 先判 `is bool` 再取数；所有字段读取都允许 `null`（缺字段不抛异常，界面显示「—」）。

**验证**：把响应里字段删掉/改类型做手工构造测试，界面只降级不崩。

## E. 系统集成

### E1. 托盘图标：先 `Visible=true` 再挂图标，可能注册成空条目

**现象**：（理论风险，已规避）早期代码顺序是 `Visible=true` → 设 `Icon`。

**根因**：`NotifyIcon` 在 `Visible=true` 时就向 `Shell_NotifyIcon` 登记，此时 `Icon` 还是 null。

**修法**：顺序改成 **先 `Icon` + `Text`，最后 `Visible=true`**；并且换图标时先赋新的、再释放旧的（避免释放了仍在被引用的 HICON）。

**验证**：日志 `tray: visible=True icon=True size=32x32`。

### E2. 本机托盘图标就是不出现 —— 用对照实验定案

**现象**：程序日志一切正常（`visible=True icon=True`、HICON 有效），但通知区永远看不到；用户确认系统设置是「显示所有图标」。

**排查过程（这套方法值得复用）**：

1. 读任务栏内部数据：`Shell_TrayWnd → TrayNotifyWnd → SysPager → ToolbarWindow32`，`TB_BUTTONCOUNT` + `TB_GETBUTTONTEXT`（跨进程读内存）→ 探测前后都是同样 10 项，一个没多；
2. 换图标来源：自绘 HICON → `Icon.ExtractAssociatedIcon(exe 内嵌 ico)` → 都一样；
3. 换启动方式：本会话启动 → `cmd start` → COM `Shell.Application.ShellExecute` → 都一样；
4. 查身份：进程是 `DESKTOP-xxx\user`、`sandboxGroups=none`、Medium IL —— 不是权限/沙箱；
5. **决定性对照**：写一个 20 行标准 .NET `NotifyIcon` demo（`tools/tray-probe.exe`），CMD 启动、用户手动双击都不出现 → **结论：这台桌面的通知区域不受理新的 `Shell_NotifyIcon` 注册，与程序无关。**

**修法**（不改程序正确性，只加兜底）：

- 每分钟静默重试一次登记（资源管理器重启后能自动恢复）；
- 增加 **`Ctrl+Alt+Q` 全局热键**，在鼠标处弹出同一个菜单（`RegisterHotKey` + `WM_HOTKEY` + `WndProc`），彻底摆脱对通知区的依赖。

**经验**：凡是「系统集成功能不生效」，先把「我的代码」和「系统行为」分开 —— 写一个最小 demo 跑同样的路径，比读十篇文档快。

### E3. SmartScreen 反复拦截

**现象**：多次弹出「Windows 已保护你的电脑 / 无法识别的应用」。

**根因**：无签名 + 无版本资源 + 每次重编译都是全新哈希（信誉从零开始）；系统侧已排除 MOTW、Defender 拦截记录、ASR 规则、CodeIntegrity 阻拦（都查过日志）。

**修法**：补版本资源/图标/manifest（见 A3）；固定目录不再搬动；必要时加 Defender 排除项；真要分发再买证书（Azure Artifact Signing 约 $10/月、Certum 个人版约 ¥600/年，证书最长 460 天且私钥必须在硬件/云 HSM）。

**验证**：属性页信息完整；同目录重复启动不再每次都拦。

### E4. 透明窗口的鼠标穿透

**现象**：投影留白区域（视觉上什么都没有）会挡住下面窗口的点击。

**根因**：如果窗口用 `Region` 或 `TransparencyKey`，「看似透明」的地方不一定是真的透明。

**修法**：`UpdateLayeredWindow` 逐像素 alpha 天然支持 —— **alpha=0 的像素不参与命中测试**，投影留白自动可点穿。

**验证**：点留白区域，能点到下面的窗口。

|---|---|
